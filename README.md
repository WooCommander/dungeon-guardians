# Хранители подземелья

Unity-прототип мобильной аркадной головоломки по ТЗ `Dungeon_Guardians_TZ_v0.1.md`.

## Что уже есть

- Каркас Unity-проекта под Android/URP.
- Данные уровней в `Assets/Resources/Levels`.
- Сеточная симуляция без зависимости от Unity Physics.
- Базовые правила: ходьба, падение, лестницы, перекладины, золото, выход, копание, восстановление блоков, поражение и простое преследование хранителей.
- Runtime-отрисовка простыми примитивами, чтобы проект запускался без готовых моделей.
- Экранные кнопки и клавиатурный ввод для быстрой проверки.

## Запуск

1. Открыть папку проекта в Unity 6.
2. Открыть любую пустую сцену или создать новую.
3. Нажать Play. `GameBootstrap` создаст камеру, HUD и игровой контроллер автоматически.

## Управление

- `A/D` или стрелки влево/вправо: движение.
- `W/S` или стрелки вверх/вниз: лестницы и отпускание перекладины.
- `Q/Z`: копать слева.
- `E/X`: копать справа.
- `R`: перезапуск уровня.
- `Esc`: пауза (продолжить, заново, в меню).
- В редакторе: `1`–`9`, `0` — уровни 1–10, `PageUp`/`PageDown` — предыдущий/следующий уровень.

Экранные d-pad и кнопки копания показываются только на телефонах и планшетах (и в Device Simulator). На ПК их нет, уровень занимает экран целиком. Их размер и прозрачность меняются в «Настройках».

«Играть» всегда начинает с первого уровня. В «Настройках» — громкость музыки и звуков (шагов хранителей), вибрация при поражении, размер и прозрачность кнопок; «Начать заново» сбрасывает прогресс и настройки.

## Предыстория

При первом нажатии «Играть» рассказывается легенда о городе под горой (`StoryScreen`): четыре абзаца печатаются по буквам на затемнённом фоне пещеры; тап или пробел дописывает абзац и листает дальше, «Пропустить» или Esc — сразу к игре. Потом история не повторяется; «Начать заново» в настройках возвращает её.

## Жизни

На каждую попытку уровня три жизни (сердечки рядом с номером уровня). Пойманный искатель остаётся на уровне каменной статуей, новый выходит со старта; собранное золото и выкопанные ямы сохраняются, хранители возвращаются на свои места. После третьей поимки — «Хранитель остановил тебя».

## Поражение

Когда хранитель касается искателя (`DefeatSequence`): тяжёлый каменный удар и мигание фонаря на шлеме; от ног вверх нарастает камень (шейдер `Resources/Shaders/Petrify.shader`), искатель дёргает руку с киркой и замирает в испуганной позе (клип `Petrify` в `build_explorer.py`); последним гаснет фонарь, из оболочки сыплется песок (`SandBurst`). Затем — «Хранитель остановил тебя» и кнопка «Попробовать снова». Если искателя замуровало в зарастающей яме, сцена короче (удар, песок из блока), надпись — «Тебя замуровало в камне», статуи не остаётся.

После победы — панель «Уровень пройден» (далее, ещё раз, меню); после последнего уровня — финал истории. Хранитель не возрождается, пока искатель ближе двух клеток к алтарю; перед появлением алтарь вспыхивает бирюзой. Игра работает только в горизонтальной ориентации.

## Формат уровня

Строки в JSON идут сверху вниз. Поддерживаемые символы:

- `#`: неразрушаемый камень.
- `B`: разрушаемый блок.
- `H`: лестница.
- `-`: перекладина.
- `E`: закрытый выход.
- `A`: алтарь возрождения.
- `.` или пробел: воздух.

Актеры и золото задаются отдельными массивами координат, чтобы тип поверхности не смешивался с объектами уровня.

Уровни (название показывается крупно в начале уровня):

1. Первые залы — знакомство, один хранитель.
2. Пробуждение стража — выбраться из запертого зала, прокопав пол.
3. Древний тайник — два хранителя, тайник с крышей из песчаника.
4. Канатная галерея — пропасть, через которую ведёт только канат.
5. Двойная стража — два хранителя и золото в карманах под полом.
6. Колодцы — ярусы связаны узкими шахтами, выход в замкнутом зале.
7. Зеркальные залы — симметричный зал и три хранителя.
8. Сокровищница — в тайник прокопаться через крышу, выбраться через пол.
9. Длинная галерея — три экрана в ширину, камера следует за искателем.
10. Шахта — три экрана вниз, проваливаться через проёмы ярусов.
11. Тёмный зал — видно только вокруг фонаря и факелов.
12. Островки света — та же карта, но хранители не заходят в свет факелов.
13. Испытание печати — заманить хранителя на плиту, врата открываются навсегда.
14. Тяжёлая плита — нажать плиту самому и успеть пробежать врата, пока они подняты.

Параметры уровня в JSON: `view` (`fit` — весь уровень на экране, `follow` — камера следует за искателем), `dark` и `lightRepelsGuardians` (тёмный зал и «островки света»), `gateMode` (`latch` — врата навсегда, `hold` — пока нажата плита и 3 с после) и `playerPressesPlates`. Клетки: `_` — нажимная плита, `|` — врата.

Уровни собираются генератором `tools/build_levels.py` (платформы, лестницы и перекладины задаются координатами). Он же расставляет факелы на подставках (`torches` в JSON) и делает блок под каждым неразрушимым — если только этот блок не нужен для прохождения. Проверяются уровни `tools/validate_levels.py`: формат, старт и выход, золото не внутри блоков, достижимость золота и выхода по правилам движения, включая копание. Ключ `--map` печатает карту с отмеченными достижимыми клетками.

```
python tools/build_levels.py && python tools/validate_levels.py --map
```

## Графика

Исходники моделей лежат в `ArtSource/` (GLB и скрипты генерации): `Characters/` — герой и хранитель с анимациями, `Environment/` — модульные детали уровня. Unity не читает GLB, поэтому модели конвертируются в FBX через Blender:

```
blender --background --factory-startup --python ArtSource/convert_to_fbx.py
```

Герой собирается отдельным скриптом из модели Tripo (`ArtSource/Characters/explorer_tripo/`): к правой кисти крепится кирка, анимации Idle, Walk, Climb, Fall и Dig задаются ключами, результат выгружается в `explorer.fbx`:

```
blender --background --factory-startup --python ArtSource/Characters/build_explorer.py
```

Хранитель собирается так же из каменного голема Tripo (`ArtSource/Characters/guardian_tripo/`). У этой выгрузки нет скелета, поэтому скрипт сам ставит кости по суставам голема, привязывает меш и задаёт клипы Idle, Walk, Climb, Fall и Struggle:

```
blender --background --factory-startup --python ArtSource/Characters/build_guardian.py
```

Общий код обоих скриптов — `ArtSource/Characters/character_rig.py`. Добавьте `-- --preview <папка>`, чтобы отрендерить ключевые позы для проверки.

Детали уровня из Tripo (сырые выгрузки лежат в `models/`, в git не попадают) импортируются скриптом: он упрощает сетку, подгоняет размер под клетку и выкладывает текстуры. Список деталей и их размеры — в `PROPS` внутри скрипта:

```
blender --background --factory-startup --python ArtSource/Environment/import_tripo_prop.py -- models/<выгрузка>.zip block_solid
```

Золото, лестницы, факелы и канат перекладин — вырезки из картинок вида спереди в `map-images/` (камера смотрит строго сбоку, поэтому они выглядят как на концепте). Скрипт убирает серый фон, делает бесшовные куски лестницы и каната (на концах перекладины — крепления с намотанным канатом) и срезает нарисованное пламя факела — в игре оно анимированное:

```
python tools/cutout_props.py
```

Дверь выхода вырезана прямо с концепта `image.png` — арка с золотой рамкой и замочной скважиной; закрытая дверь — та же, с потухшей бронзовой рамкой, открытая светится:

```
python tools/cut_door.py
```

Факелы стоят на полу на железных подставках — подставка вырезана с концепта рядом с дверью, без нарисованного огня (огонь в игре живой):

```
python tools/cut_torch_stand.py
```

Нарисованный фон пещеры кладётся в `Assets/Resources/Backgrounds/cavern.png`; без него фон собирается из процедурных силуэтов.

Начальный экран — картинка `map-images/menu.png`, экран настроек — `map-images/settings.png`. Скрипты кладут их в `Assets/Resources/Backgrounds` и вырезают кнопки (они ложатся точно на нарисованные и темнеют при нажатии), пустую плашку для окна паузы, а с настроек стирают нарисованные ползунки и проценты — поверх рисуются живые:

```
python tools/cut_menu.py && python tools/cut_settings.py
```

Музыка — `Assets/Resources/Audio/music_cavern.mp3` («Cavernous Groans»), играет по кругу через `MusicPlayer`: в меню громче, в уровне тихо, на паузе ещё тише.

Шаги хранителя вырезаны из `map-images/dragon-studio-colossal-footsteps-467495.mp3`: три отдельных удара, укороченные под темп хранителя, с лёгким перегрузом, чтобы их было слышно и на динамике телефона. `FootstepPlayer` играет удар на каждую клетку хода: чем ближе хранитель к искателю, тем громче, и со стороны хранителя. Пересобрать звуки (MP3 декодирует Blender):

```
"C:/Program Files/Blender Foundation/Blender 4.4/blender.exe" -b --factory-startup --python tools/cut_footsteps.py
```

Результат попадает в `Assets/Resources/Characters` и `Assets/Resources/Environment`. Настройки импорта задаёт `Assets/Scripts/Editor/ArtModelImporter.cs`. Уровень собирается из деталей по JSON-карте в `LevelRenderer`, анимации выбирает `CharacterView`.
